# 移动版扩展方案：分层双主控（移动底盘 + AI 语音交互）

> 目标：在现有"固定式居家监护"之上扩展出**可移动 + 带 AI 语音交互**的版本（跟随/巡逻式监护机器人）。
> 结论先行：四轮电机 STM32F103/ESP32-S3 都能扛；**板载 AI 语音必须用 ESP32-S3（或 Linux SBC）**。
> 全功能叠加会撞"引脚数量"瓶颈，因此推荐**分层双主控**架构，把"AI 大脑"与"运动控制"解耦。

## 一、为什么分层双主控

单一 MCU 同时扛"AI 语音（重、非实时）+ 四轮电机闭环（轻、硬实时）+ 全部传感器 + 屏 + RS485"会遇到两个硬约束：

1. **引脚不够**：ESP32-S3 全叠加约需 44 个 IO，扣除 Flash/PSRAM/strapping/USB 后可用仅约 30 个。
2. **实时性冲突**：语音流式处理/网络抖动会干扰电机 PID 的硬实时循环。

分层后各司其职、互不拖累，且能复用现有 `firmware/common/` 业务层与 `bsp.h` 抽象。

```
┌─────────────────────────────────────────────┐
│  AI 主控 (大脑) —— ESP32-S3 / 树莓派 / Jetson  │
│  · I2S 麦克风采集 + AFE 降噪                    │
│  · ESP-SR 离线唤醒(WakeNet)+命令词(MultiNet)    │
│  · 或 云端 ASR → LLM 对话 → TTS                 │
│  · I2S 功放放音；可选摄像头做视觉                │
│  · 决策：把"意图"翻译成运动指令                  │
└───────────────┬─────────────────────────────┘
                │  UART / CAN / USB  (motion_link 协议, 见下)
                ▼
┌─────────────────────────────────────────────┐
│  运动控制节点 (小脑) —— STM32F103RCT6 / ESP32-S3│
│  · 实时 PWM 四轮电机 (MCPWM/TIM) + 编码器 PCNT   │
│  · 电机 PID 闭环 / 麦轮解算                      │
│  · 复用现有: 雷达/传感器/报警/RS485/LVGL 屏       │
│  · 上报底盘状态(里程/电量/碰撞)给大脑             │
└─────────────────────────────────────────────┘
```

- 只想做"移动 + 电机"、语音用外接串口模块 → 单 STM32F103RCT6 也能凑合（释放 TIM2/3）。
- 要板载 AI 语音（推荐）→ 大脑用 ESP32-S3；小脑可继续用你手上的 STM32F103RCT6。
- 要做完整机器人（带视觉/大模型）→ 大脑升级成树莓派/Jetson，小脑保持 MCU。

## 二、双主控通信：motion_link 协议

大脑→小脑下发运动指令，小脑→大脑回传底盘状态。为节省引脚用**单条 UART 半双工**（也可换 CAN）。
协议实现见 `firmware/common/motion_link.c/h`（纯 C、可单元测试）。

### 帧格式（定长/变长二选一，此处用紧凑定长指令帧）

```
[0] 0xAA  帧头
[1] 0x55  帧头
[2] type  指令类型
[3] len   负载长度
[4..] payload
[..] checksum = (sum of bytes 0..4+len) & 0xFF
```

### 指令类型

| type | 方向 | 名称 | payload |
|------|------|------|---------|
| 0x01 | 大脑→小脑 | 速度指令 | int16 vx(mm/s), int16 vy, int16 wz(mdeg/s) |
| 0x02 | 大脑→小脑 | 电机直驱 | int8 pwm[4] (-100~100) |
| 0x03 | 大脑→小脑 | 使能/急停 | uint8 enable(0停/1使能/2急停) |
| 0x10 | 小脑→大脑 | 底盘状态 | int16 x_mm, int16 y_mm, int16 heading, uint8 battery, uint8 fault |
| 0x11 | 小脑→大脑 | 监护数据透传 | 复用 guardian_data 的关键字段(心率/呼吸/摔倒...) |

> 监护数据透传让大脑能把"老人状态"也纳入语音播报与云端上报，形成闭环。

## 三、ESP32-S3 移动版引脚预算（大脑或小脑二选一时）

若坚持**单颗 ESP32-S3 全叠加**，必须靠扩展芯片省脚：

| 功能组 | 直连引脚 | 省脚方案 |
|--------|----------|----------|
| 屏(SPI+CS/DC/RST/BL)+触摸 | ~8 | 保持直连(需速度) |
| 雷达 UART + RS485(+DE) | 5 | 保持直连 |
| I2C(MLX90614) + MQ7 + DHT11 | 4 | 保持直连 |
| 蜂鸣/3LED/2按键 | 6 | 挪到 PCF8574/MCP23017(I2C扩8/16脚) |
| 四轮电机 4PWM+8方向+STBY | 13 | **PCA9685(I2C 16路PWM)** + MCP23017 扩方向脚 |
| 音频 I2S麦3 + I2S喇叭3 | 6 | 保持直连(I2S必须原生脚) |
| 编码器(可选) | 4~8 | 用 PCNT，或入门版直接砍掉 |

结论：加 **PCA9685 + MCP23017/PCF8574**（都挂同一条 I2C）后，GPIO 占用可从 ~44 压到 ~26，落到 ESP32-S3 可用范围内。**分层双主控则完全不需要这么抠引脚。**

## 四、四轮电机驱动要点

- 驱动芯片：2× `TB6612FNG`（每片驱 2 电机，含方向+PWM）或 4× `DRV8833`；大扭矩用 `IBT-2`/带编码器的减速电机。
- PWM 源：
  - STM32：TIM1(4路)+TIM4(4路)。**把串口成帧从 TIM2/3 改为 UART IDLE 中断**以释放定时器。
  - ESP32-S3：`MCPWM`（带死区/刹车）或 `LEDC`（16 路）。
- 编码器闭环：STM32 用定时器编码器模式；ESP32-S3 用 `PCNT`。四轮差速/麦轮做速度 PID + 里程解算。
- 电源：电机与逻辑分开供电（电机 7.4~12V 锂电 + DC-DC 给逻辑 5V/3.3V），共地；电机反电动势大，务必加续流/隔离。

## 五、AI 语音链路（ESP32-S3）

### 离线（ESP-SR，需 PSRAM）
```
I2S PDM/数字麦 → AFE(降噪/回声消除) → WakeNet(唤醒词) → MultiNet(命令词)
                                                        → 意图 → motion_link 下发运动指令
```
适合"小云同学，过来一下""去卧室看看"这类固定命令词，无需联网、响应快、隐私好。

### 云端大模型（自由对话）
```
I2S 麦 → VAD 断句 → WiFi 流式上传云端 ASR → LLM 对话 → 云端 TTS
        → I2S 功放(MAX98357A) 播放 → 需要动作时解析出指令 → motion_link
```

### 必改配置（相对当前固定版方案）
1. `partitions.csv`：在 16MB Flash 上重划，**新增 model 分区**存声学模型：
   ```
   nvs, otadata, phy_init,
   ota_0(app,1.5M), ota_1(app,1.5M),
   model(spiffs/data, 2M),      # ESP-SR wakenet/multinet 模型
   storage(spiffs, 剩余)
   ```
2. `sdkconfig`：开 `CONFIG_USE_WAKENET` / `CONFIG_USE_MULTINET` / PSRAM(Octal) / 加大音频任务栈。
3. 音频硬件：`INMP441`/PDM 麦 + `MAX98357A` I2S 功放 + 喇叭；I2S 用原生引脚。

## 六、与现有代码的复用关系

- **运动小脑**：直接复用 `firmware/common/`（雷达/摔倒/报警/Modbus/OneNet）+ 新增 `motion` 电机模块与 `motion_link` 协议；`bsp.h` 增加电机/编码器接口。
- **AI 大脑**：新增 `firmware/esp32s3/main/audio_*`（AFE/唤醒/命令词或云 ASR）+ `motion_link` 主机端；不复用传感器逻辑。
- **上位机**：QT5 看板可增加"底盘状态/遥控"页（复用 Modbus 或新 motion_link 监视）。
- `motion_link.c/h` 放在 common，两侧共用同一份编解码，保证协议一致、可单测。

## 八、分阶段实施（在固定版跑通后进行）

1. **底盘打通**：小脑侧 PWM + TB6612 驱动 4 电机开环转 → 编码器 PCNT/定时器闭环 PID。
2. **motion_link**：实现帧编解码 + 校验，大脑↔小脑 UART 联调（先下发速度指令、回传状态）。
3. **AI 语音(离线)**：ESP-SR 唤醒词 + 命令词 → 意图映射到 motion_link 指令。
4. **AI 语音(云端)**：接云端 ASR/LLM/TTS，做自由对话 + 动作解析。
5. **整合监护**：小脑透传 guardian_data，大脑语音播报"老人状态"并上云。
6. **遥控与看板**：QT5 增加底盘遥控/状态页。

## 九、风险与注意

- **供电**：电机启动电流大，电源要留足余量，电机与逻辑分开供电并共地，否则复位/花屏。
- **实时性**：电机 PID 循环放高优先级任务/中断，语音与网络放低优先级，避免抖动。
- **引脚**：单 ESP32-S3 全叠加必须上 PCA9685/IO 扩展；分层则无此压力。
- **I2S 引脚**：音频必须用 ESP32-S3 原生 I2S 脚，不能经扩展芯片。
- **model 分区**：ESP-SR 模型较大，务必先在分区表预留，否则烧录失败。
- **安全**：移动底盘带老人场景要加碰撞/防跌落/急停，急停走 motion_link 0x03 且本地也留物理急停。
