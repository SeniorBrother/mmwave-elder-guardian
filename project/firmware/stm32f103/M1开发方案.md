## 二、M1 目标与范围（对齐 task-board）

M1 = **固件起框架**，汇合点是「点灯 + printf + FreeRTOS 跑通」。本阶段**不含传感器、不含上云、不含 RS485**，
显示只需验证到"屏能亮、能显示字符"即可，**LVGL 完整移植放到阶段2**（见第六节的对接设计，M1 先不落地）。

| # | M1 任务 | 用到的引脚/资源 | 验收方式 |
|---|---------|----------------|----------|
| 1 | SPL 工程编译通过 + ST-Link 下载 | Define: `USE_STDPERIPH_DRIVER, STM32F10X_HD` | Keil 0 error，下载成功 |
| 2 | 点灯（板载 LED2） | **PA8**（高电平点亮，接原理图核对） | 任务里每 500ms 翻转 |
| 3 | USART1 printf | PA9=TX / PA10=RX（板载 CH340+Type-C） | 串口助手 115200 看到周期日志 |
| 4 | FreeRTOS 内核移植 | SysTick 归 FreeRTOS；`configCPU_CLOCK_HZ=72000000` | `xTaskGetTickCount` 递增 |
| 5 | 雷达 USART3 接收中断成帧 | PB10=TX / PB11=RX，256000 或 115200 | 打印原始帧，能看到帧头 `53 59` |
| 6 | common 库接入 Keil | Group `common` + Include `../common` | 编译通过（先纳入 radar_proto/guardian_app） |
| 7 | 显示自检（原生API，非LVGL） | TFT PB4~PB9 | `LCD_ShowString` 显示 "M1 OK" + tick |

> 说明：任务 7 用**例程原生 API**（`LCD_Fill/LCD_ShowString/LCD_ShowIntNum`）先证明屏与驱动 OK；
> LVGL 是阶段2 的事，M1 不引入 LVGL 源码，避免把 M1 摊大。

## 三、时钟与 Keil 关键配置

- **时钟**：`system_stm32f10x.c` 里打开 `#define SYSCLK_FREQ_72MHz 72000000`（HSE 8MHz × PLL9）。
  AHB=72M / APB1=36M / APB2=72M / ADC=12M。串口波特率准 ⇒ 说明时钟确实是 72M。
- **C/C++ Define**：`USE_STDPERIPH_DRIVER, STM32F10X_HD`（HD 对应 256KB Flash，务必选对，否则向量表错位）。
- **Include Paths**：在原有基础上追加 `..\common`（即 `project/firmware/common`）。
- **Target**：芯片 STM32F103RC；IROM `0x08000000 / 0x40000`；IRAM `0x20000000 / 0xC000`。
- **Debug**：ST-Link，Port=**SW**，Flash Download 勾 **Reset and Run**。
- **勾 Use MicroLIB**（printf 重定向简单）。

**新增 Keil Group（M1）**：
- `common`：加入 `../common/` 下 M1 需要的 `.c`（先 `radar_proto.c`、`guardian_app.c`，其余按需）。
- `App`：`app_tasks.c`（FreeRTOS 任务，M1 先建最小版：Task_Led + Task_Radar）。
- `BSP`：`bsp_stm32f103.c`（用 SPL 实现 `../common/bsp.h` 接口，M1 先实现 `bsp_init/bsp_uart_send/bsp_led_set/bsp_millis/bsp_delay_ms`）。
- `FreeRTOS`：`tasks.c/queue.c/list.c/timers.c/portable/RVDS/ARM_CM3/port.c + heap_4.c`。

### 3.1 新建工程 vs 直接开现成工程（取舍）

| | 直接开现成工程 `USER/LCD.uvprojx`（**推荐**） | 新建 Keil 工程 |
|---|---|---|
| 上手难度 | 低，芯片/启动文件/路径已配好 | 中，要选芯片 + 避开 RTE 重复 startup 的坑 |
| 起点 | 已能编译出 `LCD.hex`，屏能跑 demo | 空工程，需手动加全部 SPL/源文件 |
| 主要工作 | 清理例程 `main.c` demo、加 Group | 选芯片、RTE 留空、手动加所有文件 |
| 适合 | 想最快跑通 M1 | 想要全新干净目录结构 |

> **M1 结论：直接开现成工程。** 新建工程仅在你想彻底重排目录时再做；新建时芯片选 `STM32F103RC`，
> SPL 不从 pack 选（手动加目录源码），RTE 里 `CMSIS→CORE`、`Device→Startup` **一律不勾**（避免与自带
> `core_cm3.c`/`startup_stm32f10x_hd.s` 符号重复）。

### 3.2 打开并配置已有工程 `LCD.uvprojx`（逐步，新手向）

> 菜单路径以 Keil MDK5 为准；`Options for Target` = 工具栏**魔术棒图标**，或
> `Project → Options for Target 'Target 1'`（快捷键 Alt+F7）。

1. **打开工程**：双击 `USER/LCD.uvprojx`；或 Keil 里 `Project → Open Project…` 选它。
   若提示缺器件包，先用 Pack Installer 装 `Keil::STM32F1xx_DFP` 再打开。
2. **确认芯片**：魔术棒 → **Device** 页 → 应为 `STMicroelectronics → STM32F1 Series → STM32F103 → STM32F103RC`；不是就改选它。
3. **Target 页**：Xtal 填 `8.0`；
   IROM1 起始 `0x08000000`、大小 `0x40000`；IRAM1 起始 `0x20000000`、大小 `0xC000`；
   在 Code Generation 区勾 **Use MicroLIB**（printf 重定向需要）。
4. **C/C++ 页**：
   - `Define` 框填：`USE_STDPERIPH_DRIVER,STM32F10X_HD`
   - `Include Paths`（点右侧 `…`）确认已有 `..\LCD`、`..\SYSTEM\…` 等，并**追加** `..\..\common`
     （路径相对 `.uvprojx` 所在的 `USER/` 目录；`..\..\common` 即 `project/firmware/common`）。
5. **加 Group 与源文件**：左侧 Project 树空白处右键 → `Manage Project Items…`；
   新建 Group：`common`、`App`、`BSP`、`FreeRTOS`；在各 Group 下 `Add Files…` 加入对应 `.c/.s`
   （清单见 3.0 节"新增 Keil Group"）。**不要**让 Keil 自动加 pack 的 startup/CMSIS。
6. **Debug 页**：右侧下拉选 `ST-Link Debugger` → 点 `Settings` → `Port` 选 **SW**；
   回到 Debug 页点 `Flash Download` 区勾 **Reset and Run**。
7. **Output 页**：勾 **Create HEX File**（便于烧录与后续 OTA）。
8. **编译/下载**：`Project → Rebuild all target files`（或 F7 增量编译）；0 error 后点 **Load**（F8）下载。
9. **串口验证**：设备管理器看 CH340 的 COM 号，串口助手 `115200 8N1` 打开看日志。

> 例程 `USER/main.c` 目前是出厂 demo（循环刷屏）。M1 先**保留它**验证"屏能亮、工程能跑"，
> 确认无误后再把它替换成自己的 `main`（`SystemInit + bsp_init + 建任务 + vTaskStartScheduler`）。

> 📌 **本机环境坑与解法（DFP 离线安装 / Pack Installer 卡死 / 串口 vs SWD 通道 / ST-Link 挂起问题）**
> 统一记录在同目录 [Keil本机配置备忘.md](./Keil本机配置备忘.md)。换机器或重配工程时先读它，可跳过全部已踩过的坑。

## 四、M1 引脚确认（本阶段无冲突）

M1 只用到以下引脚，**与 TFT（PB4~PB9）互不冲突**，可直接开发：

| 功能 | 引脚 | 备注 |
|------|------|------|
| 板载 LED2（点灯） | **PA8** | 高电平点亮；`README.md` 已确认，接线前万用表复核 |
| USART1 调试 printf | PA9 / PA10 | 板载 CH340G + Type-C，免外接 USB-TTL |
| USART3 雷达 | PB10 / PB11 | 帧头 `53 59`，定长 10 字节 |
| SWD 下载 | PA13 / PA14 | ST-Link |
| TFT（自检用，已在工程内） | PB4~PB9 | 见下方"⚠️ JTAG 释放" |

> ⚠️ **JTAG 释放坑**：TFT 用到 **PB4（NJTRST）**。PB3/PB4 默认属 JTAG，必须在初始化里
> 关闭 JTAG 只保留 SWD（`GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE)`），
> 否则 PB4 无法当普通 IO。例程 `lcd_init.c` 应已处理，接入后确认这段还在。

## 五、⚠️ 引脚重排方案（M2 传感器阶段前必须定稿）

例程 TFT 固定占用 **PB4~PB9**，与旧 `wiring.md` 的传感器分配冲突。由于 **OTA/W25Q64 已延期**
（PB3/PB5/PB8 空出），建议**保留 TFT 在 PB4~PB9 不动**，把冲突的传感器挪走：

| 模块 | 旧分配（冲突） | **建议新分配** | 理由 |
|------|----------------|----------------|------|
| TFT 1.8寸 | — | **PB4~PB9 保持不变** | 例程已适配，改动成本高 |
| MLX90614（体温 I2C） | PB6/PB7 = I2C1 | **软件 I2C：SCL=PB0 / SDA=PB1** | 硬件 I2C1(PB6/7)、I2C1remap(PB8/9)、I2C2(PB10/11) 全被占；MLX90614 用软件 I2C 完全可行 |
| DHT11（温湿度） | PB9 | **PB13**（单总线，GPIO+定时器读时序） | PB9 已是 TFT MOSI |
| 蜂鸣器 | PA8 | **PB14**（经 SS8050 三极管） | PA8 是板载 LED2，不能占用 |
| MQ7（CO） | PA1 = ADC1_CH1 | **PA1 不变** | 无冲突 |
| ESP8266 | PA2/PA3 = USART2 | **不变** | 无冲突 |
| RS485 | PC12/PD2 = UART5，DE/RE=PC3 | **不变** | 无冲突 |
| 按键 解除/SOS/WK_UP | PC8 / PC9 / PA0 | **不变** | 无冲突 |
| 运行/上传/雷达 LED | PC13/PC14/PC15 | **视板子是否引出**，否则复用 PA8 心跳 | 绿深板 LED 资源以原理图为准 |

> 空闲可调度引脚（重排后）：PA4/PA5/PA6/PA7（原 2.8寸 SPI1 已不用）、PA11/PA12/PA15、
> PB3/PB5/PB8/PB12/PB15、PC0~PC2/PC4~PC7/PC10/PC11。**接线前一律用万用表确认未被板载占用。**
> 定稿后需同步更新 `../../hardware/wiring.md`（把 2.8寸 ILI9341 段替换为 1.8寸 ST7735R + 上表）。

## 六、LVGL flush 后端对接设计（路线A，阶段2 落地，M1 仅记录）

用户选定：**用本例程 LCD 驱动做 LVGL 的显示后端**。对接要点如下（M1 不实现，先冻结设计）：

1. **保留底层**：`lcd_init.c`（面板初始化 + 软件 SPI 写总线 `LCD_Writ_Bus`）+ `lcd.c` 的区域写能力
   （`LCD_Address_Set(x1,y1,x2,y2)` 后循环 `LCD_WR_DATA(color)`）。
2. **新增 `lv_port_disp.c`**：
   - `disp_drv.flush_cb = my_flush`：`LCD_Address_Set(area->x1,area->y1,area->x2,area->y2)` →
     逐像素 `LCD_WR_DATA(color_p[i])` → 结束调用 `lv_disp_flush_ready(&disp_drv)`。
   - **draw buffer 用部分缓冲**（48KB RAM 装不下 40KB 全屏双缓冲）：
     建议 `128 × 20 行 × 2B = 5KB`，开 1~2 块；放静态数组，勿进 FreeRTOS heap。
3. **`lv_conf.h`**：`LV_COLOR_DEPTH 16`；关闭动画/主题/未用控件省 Flash；`LV_MEM_CUSTOM=1` 走 FreeRTOS `pvPortMalloc`（或独立静态池）。
4. **中文字库**：LVGL 不复用 `lcdfont.h`（格式不同）。方案二选一：
   - 界面**以英文/数字为主**，中文只用 LVGL「按需字库」（仅编入要显示的几十个汉字，几 KB）；
   - 或用 `lv_font_conv` 把常用汉字转成 LVGL 字体数组（注意 Flash 预算）。
5. **输入设备**：**本屏无触摸**（工程内无 XPT2046）。LVGL `indev` 用**物理按键**（PC8 解除 / PC9 SOS / PA0 WK_UP）做「上/下/确认」，或后续外加触摸模块再补 `lv_port_indev`。
6. **性能**：软件 SPI 整屏刷新偏慢（~百 ms 级），仪表盘只刷脏区可接受；
   若要动画/流畅滑动，**阶段2 可把 `LCD_Writ_Bus` 改硬件 SPI1 + DMA**（需按第五节重排引脚，SPI1 用 PA5/6/7）。
7. **FreeRTOS 集成**：LVGL 跑在独立 `Task_GUI`，周期 `lv_timer_handler()`（~30ms）；
   `lv_tick_inc()` 挂在 FreeRTOS tick hook 或一个 TIM 上。

## 七、FreeRTOS 移植要点（M1 任务4）

- 加入 `port.c`（ARM_CM3）+ `heap_4.c`；`FreeRTOSConfig.h` 里 `configCPU_CLOCK_HZ = 72000000`。
- **SysTick 冲突**：FreeRTOS 独占 SysTick 作心跳；若还要 `delay_us()` 微秒延时，
  **另用一个 TIM（如 TIM2）做 us 时基**，毫秒延时统一用 `vTaskDelay()`，别再抢 SysTick。
- 例程 `SYSTEM/delay` 的正点原子 `delay_init/delay_ms` 基于 SysTick，**移植 FreeRTOS 后要改用/避开**，
  以免与内核心跳打架（建议统一走 `vTaskDelay`，`delay.c` 仅保留裸机阶段用）。
- M1 最小任务集：`Task_Led`（500ms 翻转 PA8 + printf tick）、`Task_Radar`（有成帧标志就打印原始帧）。

## 八、雷达 USART3 成帧（M1 任务5）

- USART3(PB10/PB11)，波特率按 R60ABD1 手册（常见 256000，先试；不对再 115200）。
- `USART_ITConfig(USART3, USART_IT_RXNE, ENABLE)` + `USART3_IRQHandler` 逐字节入缓冲。
- **成帧规则**（见 `../../../docs/radar-protocol.md`）：帧头 `0x53 0x59`、帧尾 `0x54 0x43`、定长 10 字节、
  校验和 = 字节0~6 累加 & 0xFF。M1 只**打印原始帧**验证链路；M2 再交 `common/radar_proto.c` 解析。
- 收不到心率/呼吸（只有存在/运动帧）时，M2 发 `radar_build_enable_heartbeat()` 使能命令。

## 十、整机资源预算（在 27KB 基线上叠加）

**Flash（总 256KB）**

| 模块 | 占用 | 来源 |
|------|------|------|
| 显示子系统（LCD驱动+完整字库+SYSTEM，实测） | 27 KB | `LCD.map` 精确 |
| common 业务库 | ~9 KB | 估算 |
| FreeRTOS 内核 | ~12 KB | 估算 |
| App 任务层 | ~3 KB | 估算 |
| BSP（传感器/雷达/RS485/WiFi 适配） | ~5 KB | 估算 |
| 传感器驱动（软件I2C/ADC/DHT11） | ~4 KB | 估算 |
| ESP8266 AT + MQTT（阶段5） | ~8 KB | 估算 |
| LVGL 引擎（阶段2，裁剪后） | ~30~50 KB | 估算 |
| **合计（含 LVGL）** | **~98~118 KB** | **剩余 ~138~158 KB（54%~61%）** ✅ |

**RAM（总 48KB）**

| 模块 | 占用 |
|------|------|
| 显示子系统实测（RW+ZI） | 2 KB |
| LVGL draw buffer（128×20×2 ×1~2块） | 5~10 KB |
| FreeRTOS heap（`configTOTAL_HEAP_SIZE`） | 8~12 KB |
| 任务栈（6 任务，各 256~512 word） | 6~10 KB |
| 业务全局 + 串口/JSON 缓冲 | ~2 KB |
| **合计** | **~23~36 KB → 剩余 ~12~25 KB** ✅（够，但 LVGL draw buffer 与 heap 要精调） |

> 数字为工程估算（±30%），显示子系统部分为 `.map` 实测。**每次编译后按新 `LCD.map` 校准本表。**
